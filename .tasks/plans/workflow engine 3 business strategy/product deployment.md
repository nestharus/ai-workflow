We are going to have a local version and a remote version. The remote version has more of the governance stuff and has all of the models configured/ready to go. REmote is very out of the box ready easy solution. Remote you can bring your own api key or you can pay for AI credits. Local you can use oauth coding plans. Local is very much for independent devs and small teams. Remote is for larger businesses or absolute beginners. We also have a hybrid model. Remote to minimize footprint on user machine. The user just installs an application. A client. It utilizes their oauth. All of the workflow engine and hosting is remote, but remote utilizes their client as an agent executor so that htey can use their oauth subscriptions. This last one has a very tiny footprint *BUT* it still requires a lot of configuration for all of the models. For any of them you can write your own workflows. Per the jj patching, workflows work the same way. This means that you don't need a bunch of local files. You write your patches for your workflows. So local essentially becomes no footprint whatsoever for the hybrid solution. The hybrid solution will need a cheap subscription of probably $15 a month. This just enables people to work however they wish. $0 a month to run it completely locally but you have a mess on your machine. $15/mo for remote + local but you still have to configure all of your models. The workflow to model config lives remotely but you have to get them all up on your machine. Then you have fully remote version.

Local vs remote will have COMPLETELY different implementations. Remote can use full databases etc. Local is built and fine-tuned for local.
