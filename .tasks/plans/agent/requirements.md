## Problem Statement

The current update-pr.md command is too large and complex, putting excessive
load on expensive models (especially RES-07/RES-08/RES-09). Many subtasks
(linting, simple fixes) can be handled by cheaper models.
We need a hierarchical agent system that
routes work to appropriate models based on task complexity, reducing cost
while maintaining quality.

## Goal List

| ID | Goal | Description |
|----|------|-------------|
| GOAL-01 | Cost reduction | Offload work from expensive models to cheaper models |
| GOAL-02 | Quality maintenance | No degradation in review/fix quality |
| GOAL-03 | Parallel execution | Maximize throughput via parallel workers |
| GOAL-04 | Complexity routing | Smart routing based on task difficulty |
| GOAL-05 | File-based config | Minimal config.toml, instruction files at runtime |
| GOAL-06 | State isolation | Workers operate only on files explicitly listed in their context |
| GOAL-07 | Cycle management | Controlled iteration with clean exit conditions |
| GOAL-08 | Unified workflow | Single command handles local and worktree modes |

## Indexed Rule List

### Invariants

* **Precedence:** Invariants apply globally and override conflicting requirements.

| ID | Name | Description |
|----|------|-------------|
| INV-01 | No expensive models for simple tasks | Linting and simple fixes never use RES-07/RES-08/RES-09 |
| INV-02 | File isolation | Workers may modify only files explicitly listed in their context (`allowed_files`) |
| INV-03 | Commit squashing | All commits since `{initial_commit}` squash before push |
| INV-04 | No implicit state | State passed explicitly via context JSON |
| INV-05 | Metadata-only orchestration | OUTER-LOOP and INNER-CYCLE never read working tree source code contents or diff hunks; they may use only file paths + metadata and task artifacts (see ACCESS-01/ACCESS-02), while FILE/TEST/LINT workers read file contents |
| INV-06 | No AI co-authors | Never add AI/tool authorship metadata (no `Co-Authored-By` or "generated by" footers); use only the repo-configured git identity |
| INV-07 | Never defer implementation | Do not create placeholder stubs/TODOs; implement the requirement now or explicitly raise a blocker/clarification; deferral is allowed only when the current plan/task file explicitly authorizes it |
| INV-08 | Minimize orchestration context | Orchestrators store only paths, counts, and brief summaries; never embed raw file contents or diff hunks in prompts/artifacts; persist large inputs/outputs as files and pass references |
| INV-09 | Mandatory worker delegation | OUTER-LOOP and INNER-CYCLE never directly handle comment resolution, code edits, tests, or lint fixes; they always spawn FILE/TEST/LINT workers and aggregate results |
| INV-10 | No concurrent sessions per working_dir | Concurrent `/update-pr` sessions in the same `working_dir` are not supported (shared `tmp_folder`/`review_dir`); session start cleanup assumes exclusive access |

### Orchestration Access Rules

| ID | Name | Description |
|----|------|-------------|
| ACCESS-01 | Allowlist | Explicitly allowed operations for OUTER-LOOP and INNER-CYCLE |
| ACCESS-02 | Denylist | Explicitly prohibited operations for OUTER-LOOP and INNER-CYCLE |

**ACCESS-01 — Allowed operations (OUTER-LOOP, INNER-CYCLE)**

* File system metadata and artifact management only:
  * `ls/find/stat/wc` scoped to `{tmp_folder}` and `{review_dir}`
  * Read/parse JSON/text artifacts under `{tmp_folder}` and `{review_dir}` (e.g., `thread_*.json`, `local_*.json`, `coderabbit_*.json`, `aggregated.json`)
  * Use `jq` to extract keys/paths from artifact JSON
  * Delete artifacts under `{tmp_folder}` and `{review_dir}` per FILE-10/13/15
* Git metadata only (no source/diff hunks):
  * `git status --porcelain`
  * `git diff --stat ...`, `git diff --name-only ...`
  * `git ls-files` (filenames only)
  * `git rev-parse ...`, `git branch --show-current`
* Orchestration-related entrypoints that operate on artifacts/metadata:
  * `uv run pr get-pr`, `uv run pr setup-worktree`, `uv run pr fetch-threads`
  * `uv run review.coderabbit` (writes review artifacts to `{review_dir}`)
  * `uv run pr parse-coderabbit`, `uv run pr aggregate-tasks`
  * `uv run pr post-deferred-replies`

**ACCESS-02 — Prohibited operations (OUTER-LOOP, INNER-CYCLE)**

* Any direct read/parse of working tree source code files outside `{tmp_folder}`/`{review_dir}` (delegate to FILE/TEST/LINT workers instead).
* Any diff-hunk or file-content commands, including but not limited to:
  * `git diff` without `--stat`/`--name-only`
  * `git show`/`git blame` (content-bearing)
  * `cat/less/head/tail`, `rg/grep`, `sed/awk` on repo source files
* Any inclusion of raw file contents or diff hunks in orchestration prompts/artifacts (see INV-08).

### Model Routing Rules

| ID | Name | Description |
|----|------|-------------|
| ROUTE-02 | Classifier model | Complexity classification uses Ministral 3B (RES-04) for prompts ≤2500 chars, GLM 4.7 (RES-03) fallback for larger prompts |
| ROUTE-03 | Outer loop model | Orchestration uses GPT 5.2 None (RES-05) |
| ROUTE-04 | Inner cycle model | Cycle management uses GPT 5.2 Medium (RES-06) |
| ROUTE-05 | Lint model | Linting always uses Minimax (RES-10) |
| ROUTE-06 | Simple handler | Low-ambiguity short tasks use Minimax (RES-10) |
| ROUTE-07 | Complex handler | High-ambiguity or long tasks use Codex Medium (RES-07) |
| ROUTE-08 | Test fix routing | Test fixes route by failure severity to RES-07/08/09 |

Rationale: use local Ministral 3B (with GLM 4.7 fallback) + Minimax for cheap routing and simple edits; reserve Codex models for ambiguity-heavy comment handling and test fixing to control cost.

### Complexity Classification Rules

| ID | Name | Description |
|----|------|-------------|
| CLASS-01 | Ambiguity score | Rate 1-5: 1-2 = precise, 3-5 = general |
| CLASS-02 | Character threshold | < 500 chars = short, >= 500 chars = long |
| CLASS-03 | Combined routing | `if ambiguity <= 2 AND chars < 500 then simple else complex` |
| CLASS-04 | Classifier prompt | Ministral 3B scores ambiguity from task text (GLM 4.7 fallback for >2500 chars) |

### Workflow Mode Rules

| ID | Name | Description |
|----|------|-------------|
| MODE-01 | Local mode | No ticket ID: review uncommitted or HEAD~1 |
| MODE-02 | Worktree mode | With ticket ID: setup worktree; cycle 1 uses threads-first review source |
| MODE-03 | Mode detection | First **non-flag** argument matching `[A-Z]+-\d+` indicates worktree |
| MODE-04 | Loop flag | If the first argument is `--loop`, enable continuous cycles |
| MODE-05 | Argument parsing | Parse args into `has_loop`, `ticket_id`, and `local_tasks_text` (text after parsed flag/id) |
| MODE-06 | Single-cycle default | Run exactly one cycle unless `has_loop=true` |
| MODE-07 | Argument grammar | `update-pr [--loop] [TICKET-ID] [local_tasks_text...]` where `local_tasks_text` preserves spaces |
| MODE-08 | Threads-first (cycle 1) | In worktree mode on cycle 1, fetch PR threads; because `tmp_folder` is session-cleaned (FILE-13) and `fetch-threads` clears `thread_*.json`, the thread existence check cannot be satisfied by stale artifacts; if any `thread_*.json` exist after fetch, skip CodeRabbit and treat them as tasks |
| MODE-09 | CodeRabbit fallback | In worktree mode on cycle 1, run CodeRabbit with `--base {base_branch}` only when no threads exist; on cycles > 1, always use `--base-commit HEAD~1` |
| MODE-10 | Local CodeRabbit target (cycle 1) | In local mode on cycle 1, use `--type uncommitted` only when uncommitted changes exist; otherwise use `--base-commit HEAD~1` |

### Worktree Setup Rules

| ID | Name | Description |
|----|------|-------------|
| WT-01 | Get PR metadata | In worktree mode, call `uv run pr get-pr {ticket_id}` and require `{worktree_path, pr_number, base_branch, branch_name}` in the response |
| WT-02 | Setup worktree | If the current directory is not already the expected worktree, call `uv run pr setup-worktree {ticket_id}` and `cd` into `worktree_path` |
| WT-03 | Validate worktree context | Validate `{worktree_path}` exists and is a git worktree; validate `pr_number` is an integer and `base_branch` is non-empty before entering cycles |

### Cycle Management Rules

| ID | Name | Description |
|----|------|-------------|
| CYCLE-01 | Max cycles | Hard limit of 10 cycles per run |
| CYCLE-02 | Clean exit | Exit when no tasks remain after aggregation |
| CYCLE-03 | Cycle sequence | review → parse → handle → test → commit → (post replies + collect local replies) → cleanup |
| CYCLE-04 | State tracking | Track modified files, cycle summaries across cycles |
| CYCLE-05 | Cycle cleanup | Reset `{tmp_folder}` per FILE-10 so later cycles do not see stale tasks |
| CYCLE-06 | Cleanup on all exits | INNER-CYCLE must run cycle cleanup (ALG-INNER-06) even when exiting `clean` or `error` (e.g., `finally` semantics) |

### Parallel Execution Rules

| ID | Name | Description |
|----|------|-------------|
| PAR-01 | File handlers | Spawn one handler per file, run in parallel |
| PAR-02 | Test runners | Spawn one runner per changed .py file, run in parallel |
| PAR-03 | Lint fixers | Spawn one fixer per file, run in parallel |
| PAR-04 | Global tasks | `__global__` tasks process sequentially after file tasks |
| PAR-05 | Multi-file tasks (known files) | If a task requires edits across multiple known files, schedule a single worker with `allowed_files` covering the full set and ensure no other worker touches any of those files in the same cycle |
| PAR-06 | Scope expansion (unknown files) | If a worker discovers additional required files not present in `allowed_files`, it must return `required_files[]`; INNER-CYCLE schedules follow-up work sequentially (like `__global__`) with expanded `allowed_files` and without parallel overlap |

### State Management Rules

| ID | Name | Description |
|----|------|-------------|
| STATE-01 | Session state | `initial_commit`, `commits_made`, `loop_start_time` |
| STATE-02 | Cycle state | `cycle`, `cycle_start_time`, `files` |
| STATE-03 | Aggregate state | `all_modified_files`, `cycle_summaries` |
| STATE-04 | Context passing | State passed via JSON in agent prompts (includes per-worker `allowed_files`) |
| STATE-05 | PR metadata | In worktree mode, store `pr_number` and `base_branch` for MODE-08..MODE-09 |
| STATE-06 | Local tasks | Store `local_tasks_text` and whether local tasks were imported |
| STATE-08 | Local task responses | Track `local_task_responses[]` extracted from `local_*.json` before FILE-10 cleanup; truncate any stored response text to satisfy INV-08 |

### Finalization Rules

| ID | Name | Description |
|----|------|-------------|
| FIN-01 | Final lint | Run lint on all files in `all_modified_files` |
| FIN-02 | Commit lint | Commit any lint fixes as separate commit and increment `commits_made` |
| FIN-03 | Squash condition | If `commits_made > 1`, squash all commits from `{initial_commit}` into a single commit (INV-03) |
| FIN-04 | Push | Push to origin after squashing; if no upstream is configured, the first push must set upstream (e.g., `git push -u origin HEAD`) |
| FIN-05 | Deferred replies | In worktree mode, post replies only for PR comment threads (including pathless/global PR threads) from `thread_*.json` artifacts in `{tmp_folder}` by running `uv run pr post-deferred-replies --pr {pr_number} --threads-dir {tmp_folder}` **before** per-cycle cleanup deletes `{tmp_folder}` (FILE-10); do not post replies for local tasks (`local_*.json`) or CodeRabbit tasks (`coderabbit_*.json`) |
| FIN-06 | Local replies | Collect `deferred_reply` from `local_*.json` in `{tmp_folder}` into session state **before** per-cycle cleanup deletes `{tmp_folder}` (FILE-10), for inclusion in the final output summary |
| FIN-07 | Final cleanup | After FIN-05/FIN-06 (or on early termination), delete remaining session artifacts per FILE-15 |

### File-Based Configuration Rules

| ID | Name | Description |
|----|------|-------------|
| FILE-01 | Agent files | Agents defined in `.agents/agents/*.md` with YAML frontmatter routing rules |
| FILE-02 | Model configs | Model backends defined in `.agents/models/*.toml` |
| FILE-03 | Context JSON | Pass file path + context JSON to spawn agents |
| FILE-04 | No hardcoded prompts | All prompts in external markdown files |
| FILE-05 | Task artifact dir | `tmp_folder={working_dir}/.tmp/pr-review/` and all session task artifacts are written here |
| FILE-06 | PR thread task schema | `thread_*.json` includes `index`, `thread_id`, optional `path`, optional `line`/`start_line`/`end_line` (plus optional original line fields), `first_author`, `comments[]` with `body`, `author`, `reactions[]`, plus optional `deferred_reply`; when `path` is absent the thread is a global/PR-level comment and still eligible for FIN-05 |
| FILE-07 | Local task schema | `local_*.json` includes `index`, `origin=LOCAL`, `content`, `comments[]` with `body`/`author`, plus optional `deferred_reply` |
| FILE-08 | Review artifact dir | `review_dir={working_dir}/.review/`; `uv run review.coderabbit --output-dir {review_dir} -- ...` runs synchronously and writes a timestamped `review_file` under `{review_dir}`; the caller extracts the `review_file` path from stdout using `uv run pr extract-review-path` |
| FILE-09 | Parallel-safe paths | All artifact paths (`tmp_folder`, `review_dir`, `review_file`) resolve relative to `working_dir` to avoid cross-worktree collisions |
| FILE-10 | Per-cycle cleanup (full reset) | After each cycle, delete `review_file` (if present), then delete and recreate `{tmp_folder}` (`rm -rf {tmp_folder}; mkdir -p {tmp_folder}`); this guarantees no stale artifacts of any kind (including `thread_*.json` / `local_*.json` / unexpected files) persist across cycles |
| FILE-11 | CodeRabbit task schema | `coderabbit_*.json` includes `index`, `origin=CODERABBIT`, `path`, `line`/`start_line`/`end_line`, optional `type`, `content`, and `comments[]` with `body`/`author` |
| FILE-12 | Aggregated task schema | `aggregated.json` includes `{ files: string[], tasks_by_file: { [path]: string[] }, task_count: number }` where `tasks_by_file[path]` is a list of task filenames and `tasks_by_file.__global__` holds tasks with no `path` |
| FILE-13 | Session start cleanup | Before cycle 1, delete stale session artifacts by removing and recreating `{tmp_folder}`; this prevents `thread_*.json`/`local_*.json` leakage across runs |
| FILE-14 | No retained task artifacts | Do not keep an archive directory or preserve task artifacts across cycles; any data needed for final output must be extracted into session state before FILE-10 deletes `{tmp_folder}` |
| FILE-15 | Final cleanup | After FIN-05/FIN-06 (or on early termination), delete `{tmp_folder}` and any remaining `review_file` to guarantee clean runs |

### ALG-INNER-ROOT: One complete inner cycle (review → parse → handle → test → commit → cleanup)

```mermaid
flowchart TD
  %% Rules: CYCLE-02..CYCLE-06, MODE-08..MODE-10, PAR-01..PAR-06, STATE-01..STATE-04, FILE-05, FILE-10, FIN-05..FIN-06
```
