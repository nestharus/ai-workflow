# Documentation File Mapping: PROJECT vs GENERAL

## Overview

This document maps all YAML documentation files from their current locations to their
new locations in the reorganized structure.

### PROJECT vs GENERAL

- **PROJECT**: Documentation that references actual project files (`app/*`) and shows
  how to implement features in THIS specific project
- **GENERAL**: Documentation that describes framework-agnostic patterns, framework-specific
  patterns, or protocol-level patterns without referencing specific project files

### Naming Convention

- PROJECT files: `project.module.<pattern>.yml`
- GENERAL files: `general.module.<pattern>.yml`

### Target Modules

| Module | Description |
|--------|-------------|
| `rest` | REST/HTTP protocol patterns (URL structure, HTTP methods, status codes, versioning) |
| `fastapi` | FastAPI framework-specific patterns |
| `python` | Python language-specific patterns (docstrings, language features) |
| `surrealdb` | SurrealDB database-specific patterns |
| `elasticsearch` | Elasticsearch search-specific patterns |

### python.api-patterns.yml → project.rest.api-patterns.yml

This file is **misplaced** in the `python/` directory. Its content describes REST/HTTP
semantics including:

- URL structure and resource naming
- HTTP methods (GET, POST, PUT, PATCH, DELETE)
- Status codes and their meanings
- Content negotiation
- API versioning strategies

While these are **protocol-level patterns** that could apply to any language or framework
implementing REST APIs, the file contains multiple references to project-specific paths:

- `app/contracts/errors.py` - project error contracts
- `app/contracts/` - project contract models
- `app/core/factory.py` - project application factory
- `app/core/exceptions.py` - project exception handlers

Due to these `app/*` references, the file is classified as **PROJECT** despite its REST
focus. The file should be moved to `project/rest/` with the naming convention
`project.rest.api-patterns.yml`.

**Cleanup Required**: To make this file truly GENERAL in the future, the `app/*`
references must be removed or generalized to pseudo-paths (e.g., `<project>/contracts/`).
